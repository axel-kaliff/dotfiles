# Notes

Persist what this session *learned* into `claude_session/notes/`: one topic note per question, an index a fresh agent reads first, and raw agent reports kept verbatim. The handoff carries in-flight state; notes carry knowledge.

**Core principle:** restorable compression. Every fact carries an as-of date and a source (URL or path), so the fetched content can leave the context and be recovered later.

**Announce at start:** "Persisting notes."

## Layout

```
claude_session/notes/
  INDEX.md           regenerated by scripts/index.sh — one line per note, with its size
  <topic>.md         topic note (format in Step 4)
  raw/               verbatim agent reports and long tool output, append-only
  sources/<topic>/   copied primary material (headers, demos, specs) — the scratchpad dies with the session
```

## Step 1: Ensure the layout exists

```bash
root=$(git rev-parse --show-toplevel 2>/dev/null || pwd)
mkdir -p "$root/claude_session/notes/raw" "$root/claude_session/notes/sources"
if git rev-parse --is-inside-work-tree >/dev/null 2>&1; then
  ex="$(git rev-parse --git-common-dir)/info/exclude"; mkdir -p "$(dirname "$ex")"
  grep -qxF 'claude_session/' "$ex" 2>/dev/null || echo 'claude_session/' >> "$ex"
fi
ls "$root/claude_session/notes" "$root/claude_session/notes/raw"
```

## Step 2: Read what is already there

Read `INDEX.md`, then every topic note the new knowledge touches. Merge into those; a new file only for a new question.

## Step 3: Identify unpersisted knowledge

Scan the conversation for:
- research and docs-agent reports, web and library lookups: verified APIs, versions, install stories, licences
- experiment results: setup, result, conclusion
- comparisons and trade-offs between options
- dead ends, with why each failed
- open questions and design implications

Skip what the code, the commits, or `DECISIONS.md` already say. Choices between alternatives go through `/decisions`, not here.

## Step 4: Write

New topic — create `<topic>.md`:

```markdown
# <Title>
- Question: <the one-line question this note answers>
- Status: <verified | partial | stale>
- Updated: YYYY-MM-DD

## Summary
<≤15 lines: the current answer. Rewritten only when the answer changes.>

## Findings — YYYY-MM-DD
- <fact> (as of YYYY-MM, source: <URL or path>)

## Dead ends
- <what was tried> — <why it failed>

## Open questions
- <question>

## Sources
- <URL or path> — <what it holds>
```

Existing topic — append a new `## Findings — YYYY-MM-DD` section with `cat >>`, bump `Updated`, and rewrite `## Summary` only if the answer changed. A superseded fact stays in place, marked `[superseded YYYY-MM-DD]`; nothing is deleted.

Agent reports go verbatim to `raw/<topic>-YYYY-MM-DD.md` before distilling. Primary material worth keeping (a header, a demo script, a spec excerpt) is copied under `sources/<topic>/`.

## Step 5: Regenerate the index

```bash
${CLAUDE_SKILL_DIR}/scripts/index.sh "${CLAUDE_PROJECT_DIR}"
```

## Step 6: Report

List each note created or updated on one line. Done when every item from Step 3 is in a note and INDEX.md lists every note.

## Delegating research

When spawning research agents, add to their prompt: "Write your full report to `claude_session/notes/raw/<topic>-<date>.md`; return a summary under 300 words." The report lives on disk from the moment it exists — compaction cannot lose it — and `/notes` distils it later.
